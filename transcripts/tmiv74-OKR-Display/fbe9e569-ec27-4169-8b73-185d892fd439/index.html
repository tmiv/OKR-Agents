Recommendation: a proactive Briefing panel. When a document loads, and again after every commit, the assistant audits the whole tree unprompted and returns a ranked list of three to six findings. Each finding is a card with a title, a one-line reason, the nodes involved, and an optional ready-made fix. Hover a card and the camera previews those nodes. Click it and the scene flies there. Click "Fix" and the actions go through the existing commit path, so undo covers it. The list re-runs after the fix, so the user watches it shrink.

Why this over the alternatives you have queued:

  • It is the attention-barrier story made visible. Polaris has 135 nodes and 61 teams. Nobody reads that. The briefing turns it into five cards before the user touches anything. That is exactly the "keeping it honest and small" job the Depth and Focus doc says replaces drawing the tree.
  • It is agent-initiated, human-decided. Today the assistant only answers. Here it acts first and proposes, and the user only chooses. That honours the "AI drafts, humans decide" principle without any auto-apply.
  • It extends the demo script, not replaces it. Load, briefing appears, hover, fix, watch the list shrink, undo. Ninety seconds, no typing.
  • Everything it needs exists. One endpoint with a new audit mode, an additive optional findings array on the response schema, the preview-on-hover mechanism from the panel links, commit() with actor and reason, and the topbar weak-link count as the badge that opens the panel. The service already validates highlight ids, so finding ids get the same treatment.

The runner-up is persona chat, mode 1 of the team discussions. It is about two hours of work, but it produces another chat tab, and the user still has to know what to ask. It fails your "at a glance" test. The better move is to fold it in as a stretch: each finding names the owning team, and an "Ask the team" button opens a persona tab with that finding as the opening message. That gives you the teams-as-agents demo on top of the briefing for the cost of one enum value and one prompt block.
