#62026-09-12T01:20:06.780Z

in this system can objectives have objectives

1 bash

Not in practice, though the data format would tolerate it. The system is a strict three-rung ladder: company → objective → key result. Where that is enforced:

  • Schema semantics: schema/index.js:205 checks that a child's level is exactly one rung below its parent. An objective under an objective is only a warning, not an error, so a hand-authored or imported file with nested objectives loads and renders.
  • Node editor: Detail.svelte:117 offers KRs only objectives as parents and objectives only the company root. The "Add child" button at Detail.svelte:141 creates an objective under the company and a KR under an objective, and offers nothing under a KR.
  • Prompt: prompt.js:232 describes the three levels and prompt.js:252 forbids changing a node's level. The model is not told nesting is possible.
  • Service validation: validate.js:194 only guards against a second company root. A model-proposed add with level: "objective" and an objective parent would pass, but the prompt steers away from it.
  • 3D layout: the DAG layout is level-agnostic, so nested objectives would display fine, just one rung deeper.

So the answer today is: the file format allows it with a warning, the UI and prompt do not offer it, and nothing crashes if it appears.

If you want objective-under-objective as a real feature (sub-objectives or multi-level org hierarchies), the changes are: relax the ladder check to "objective may hang off company or objective", widen the parent select and Add button in Detail, and tell the prompt. That is a small plan. Say so and I'll write it.
